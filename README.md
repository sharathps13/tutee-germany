# Tutee Connect — Germany landing page

A static clone of the reference site <https://pageus.netlify.app/#/> with the content localised to
Germany. Same layout, same compiled Tailwind stylesheet, same animations — only the copy, the
photographs, the currency glyph and the institution dataset are German.

## Files

```
index.html               the landing page          (generated — do not hand-edit)
universities.html        the institution directory (generated — do not hand-edit)
assets/css/main.css      the reference site's compiled Tailwind output, shipped verbatim
assets/css/quicksand.css the webfont, self-hosted
assets/fonts/            Quicksand woff2 subsets

Start Local Server.command   double-clickable wrapper for serve.py
```

## How it was built

Everything is generated by the shared toolchain in `../_tooling`. The reference site is a React
SPA; its rendered DOM was captured once so the markup and every Tailwind class match the original
exactly, and the compiled stylesheet is shipped as-is — which means **a class only works if it is
already in that CSS**.

```
reference DOM  ->  _tooling/fragments-uk/     (the UK section fragments)
                     |  localise_de.py        (whole-text-node replacements, German copy)
                     v
               _tooling/fragments-germany/
                     |  assemble.py germany   (stitches sections, injects the data-* hooks)
                     |  build_unipage.py germany
                     v
               GERMANY/index.html + universities.html
```

`localise_de.py` also generates this folder's `main.js` and `services-data.js` from the UK
originals, because their copy is part of the page even though it isn't in the HTML.

To rebuild:

```bash
cd "/Users/tuteeconnect/Landing Page/_tooling" && python3 build_dataset_de.py && python3 localise_de.py && python3 assemble.py germany && python3 build_unipage.py germany && python3 verify_site.py germany
```

## Fidelity — measured, not hoped for

`localise_de.py` diffs the tag+class skeleton of every fragment against its UK input and refuses to
write if anything moved. The built result was then diffed against the other pages:

- `universities.html` is **structurally identical** to the UK, Canadian and Irish pages —
  402 elements, zero differences.
- `index.html` has **1850 elements, exactly matching Canada and Ireland**, and differs from the
  Irish page by **one single element**: the `bg-[url('…/germany-city.jpg')]` class token. Nothing
  else in the DOM changed. (The two-element gap to the UK's 1852 is the documented
  `circle-pound-sterling` → `circle-euro` swap, which has one `<path>` fewer.)
- **Animation parity is exact** against all three existing pages: `.reveal` 42, `transition-delay`
  24, `animate-fade-in` 1, `animate-bounce` 3, `animate-marquee` 1, `animate-float` 1,
  `transition-all` 193, `transition-transform` 28, `duration-*` 234.
- The `IntersectionObserver` block that drives the scroll reveals is **byte-identical** to the UK's.
- Rebuilding the UK, Canadian and Irish pages after these toolchain changes still reproduces them
  **byte-for-byte** — that comparison is the regression test for anything in `_tooling`.

> Note: `.reveal` animations are driven by `IntersectionObserver`, which **does not fire in a hidden
> or backgrounded browser pane**, and CSS transitions are frozen there too. If reveals look broken
> while automating a browser, check `document.visibilityState` before believing it.

## Four deliberate divergences from the UK page

1. **The euro glyph.** `swap_currency='euro'` gives `circle-euro`, as on the Irish page. A `$` or a
   `£` on a German page reads as an error, so `verify_site.py` treats both as leaks.

2. **`students` instead of `offerRate`.** The UK page's `offerRate` is an invented placeholder (all
   499) and is still flagged as a launch risk in `../UK/README.md`. Germany renders the **enrolment
   the HRK register actually publishes**, and the card label changes from "Offer rate" to "Enrolled
   students". It is a size, not a quality score.

3. **Umlaut-folded search.** Extends the accent folding written for Canada. German needs three
   things a plain NFD fold does not give: `ß` does not decompose at all and is mapped to `ss`;
   Germans routinely transliterate rather than accent, so `ue`/`oe`/`ae` are collapsed *after* the
   NFD pass, which maps `München`, `Munchen` and `Muenchen` onto one key; and a searched-but-never-
   rendered `alt` field carries the English names the institutions use for themselves
   ("Technical University of Munich"), which appear nowhere in the German register. Without that
   last one the directory is unusable for an applicant who only knows the English name.

4. **Tuition-free is the headline, not fees.** The reference's whole money story is built around
   £12,000–£38,000 tuition. German public universities charge none, so the copy is rebuilt around
   the blocked account (€11,904/yr), the semester contribution and the one Baden-Württemberg
   exception. See `../_tooling/GERMANY_SPEC.md`.

## The dataset

379 institutions from the **Hochschulkompass list published by the Hochschulrektorenkonferenz** —
the official register of every state and state-recognised higher education institution in Germany
(`hs_liste.txt`, snapshot in `_tooling/reference/`). Nothing is invented and the list is not padded.

The register holds 388. The nine **Verwaltungshochschulen** are excluded, and that is the only
filter applied: entry to them runs through a German civil-service traineeship rather than an
application an international student can make, and the reference card markup states
`Intl. Admits: Yes` for every institution it renders — so listing them would assert something
untrue about all nine. `build_dataset_de.py` asserts that exactly nine are dropped, so a register
update that changes the count fails the build rather than passing silently.

- **Ordering:** the 49 German institutions in the **QS World University Rankings 2026** first, in
  world-rank order; the remaining 330 by statutory category then alphabetically, rendering a dash.
  49 ranked is comfortably past the 12 the home-page carousel needs.
- **Flagship group:** **TU9**, the nine leading Technische Universitäten — the cohort most Indian
  engineering applicants target. Replaces the UK's Russell Group and Canada's U15.
- **Regions:** all 16 Bundesländer, under their standard English names.
- **Editorial fields** are marked as such in the generated file's header: `programs` is an
  indicative subject descriptor, written per institution for the 49 ranked ones and derived by rule
  from the registered name and category for the tail.

## Known issues to settle before launch

1. **Annual figures need re-checking each intake.** The blocked-account amount, the Blue Card
   salary thresholds, the minimum wage, the 140-day work allowance and the anabin entry criteria
   all move. They are flagged **[annual]** in `_tooling/GERMANY_SPEC.md`.
2. **`programs` is editorial**, not a course inventory, and 330 of the 379 descriptors are
   rule-derived. Fine as a descriptor; do not present it as an admissions guarantee.
3. **`Intl. Admits: Yes` is still hardcoded** in the reference card markup for every institution.
   Excluding the Verwaltungshochschulen removed the case where it was flatly false, but it remains
   a blanket claim rather than per-institution data — as on the UK, Canadian and Irish pages.
